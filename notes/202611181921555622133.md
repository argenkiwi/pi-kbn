Board state lives in the kanban tool result details (plus kanban-state custom entries from /kanban on|off|clear) and is replayed from ctx.sessionManager.getBranch() on session_start/session_tree, last snapshot wins, so branches/forks/resume are correct with no external file. The kanban rules go into the system prompt as static text, while the per-prompt board snapshot is a hidden before_agent_start message; this keeps the system prompt stable so prompt caching survives. Confirmation is any non-extension input event, and edit/write are blocked in tool_call. Because sibling tool calls are preflighted before execution, kanban start must be called in its own step before editing (stated in the rules and block reason). interrupted is runtime-only: set on session_start when a task is still doing and on agent_end with a doing task, cleared on agent_start (not on input, because before_agent_start still needs it to inject the resume note). Tool errors must be thrown from execute to set isError.
